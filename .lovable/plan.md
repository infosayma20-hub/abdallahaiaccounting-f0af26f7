# خطة إعادة تصميم شاشة الإشعارات الدائنة/المدينة (D365 FinanceShell)

## النطاق
- شاشة القائمة `/credit-notes` و `/debit-notes` → `CreditDebitNotesPage.tsx`
- شاشة الإنشاء/التعديل/العرض `/credit-notes/new` → `CreditDebitNoteCreatePage.tsx`

كل الوظائف الحالية (حفظ، ترحيل، حذف، سحب بنود، ربط فاتورة، ترحيل محاسبي، سجل ضريبي) **تبقى كما هي دون تغيير في المنطق**. التغيير بصري + إضافات تنقل + مركز تكلفة.

---

## 1) شاشة القائمة — تبديل إلى `FinanceShell`

**الاستبدال:** إزالة `AccountingShell + PageHeader + Cards يدوية` واستخدام `FinanceShell` القياسي الموجود في `src/components/finance/shell/`.

المكونات:
- **Breadcrumb:** الرئيسية / المبيعات (أو المشتريات) / الإشعارات الدائنة
- **ActionPane (شريط أوامر D365)** بمجموعات:
  - **جديد:** إنشاء إشعار (Alt+N)
  - **تعديل:** فتح للتعديل، حذف (على السطر المحدد)
  - **استعلام:** فتح للعرض (Read-only)، تحديث القائمة
  - **تصدير:** Excel / PDF (اختياري — إن وجد helper `excel-export`)
- **FiltersPanel:** حقول (الحالة، التاريخ من/إلى، العميل، رقم الإشعار) مع `storageKey="credit-notes-list"` لدعم My Views.
- **KPI Cards خفيفة** أعلى الجدول (نفس القيم الحالية: عدد، إجمالي، مسودات) بنمط D365 هادئ (بدون ألوان زاهية).
- **الجدول** بنفس الأعمدة الحالية + عمود “الحالة” بألوان Badge محايدة.

---

## 2) شاشة الإنشاء/التعديل — تبديل إلى `FinanceShell` + `FastTabs`

**الاستبدال:** إزالة الـ Cards المسطحة واستخدام:
- `FinanceShell` كإطار خارجي.
- `FastTabs` (Dynamics D365 sections قابلة للطي) بالأقسام:
  1. **رأس الإشعار** — العميل/المورد، التاريخ، الفاتورة المرتبطة، السبب
  2. **البنود** — الجدول الحالي كما هو
  3. **الملاحظات والمرفقات**
  4. **مركز التكلفة** — *جديد* (انظر قسم 4)

**ActionPane** يحتوي على:
- **حفظ:** حفظ مسودة (Ctrl+S) — يستدعي `handleSave(true)` الحالي
- **ترحيل:** حفظ + ترحيل (Ctrl+Enter) — يستدعي `handleSave(false)` الحالي
- **تنقل:** *جديد* — السابق (Alt+←) والتالي (Alt+→) — انظر قسم 3
- **استعلام:** *جديد* — فتح Popover بحث عن إشعار بالرقم/العميل والانتقال إليه
- **إجراءات:** حذف، رجوع للقائمة

---

## 3) التنقل السابق/التالي (جديد)

يعمل بجلب معرفات الإشعارات المرتبة زمنياً لنفس النوع ونفس المالك ثم الانتقال بينها:

```ts
// عند الفتح في وضع تعديل/عرض:
const { data } = await supabase
  .from("invoices")
  .select("id")
  .eq("user_id", ownerId)
  .eq("invoice_type", dbType)
  .order("created_at", { ascending: false });
// نبني index list ونحدد prev/next
```

- أزرار السابق/التالي معطلة عند الحدود.
- تحفظ أي تعديلات معلقة قبل التنقل (تحذير إن وجدت).

---

## 4) مركز التكلفة (جديد)

- إضافة عمود `cost_center_id` على مستوى الرأس (invoice) و/أو على مستوى البند.
- في هذا التصميم: **رأس الإشعار فقط** (كفاية لطلب المستخدم؛ يمكن توسيعه لاحقاً).
- استخدام `useCostCenters()` الموجود لعرض قائمة منسدلة (leaf-only، active).
- عند الترحيل يُمرَّر `cost_center_id` مع `payload` إلى جدول `invoices` وإلى قيد `transactions` (نفس الحقل).

**ملاحظة:** لا نغيّر أي منطق ترحيل محاسبي؛ فقط نضيف الحقل الاختياري.

---

## القيود
- لا تعديل على منطق الترحيل، الترقيم، الضريبة، أو الحذف.
- لا تعديل على جدول `invoices` DB (الحقل `cost_center_id` موجود أصلاً حسب `useCostCenters` line 47).
- كل النصوص عربية RTL، ألوان تستخدم tokens (لا `text-white`/`bg-emerald-*` مباشرة داخل الشل الجديد).
