
# خطة "بضاعة آخر المدة" — تطبيق IAS 2 / IAS 1 كامل ومربوط بشجرة الحسابات

## 1) نتيجة الفحص المحاسبي والتقني

### أ. نتائج قراءة قاعدة البيانات (شجرة الحسابات الحالية)
- `1140 المخزون` — أصل، محمي، `system_role = 'inventory'` ✅ موجود
- `1141`, `1142` — حسابات مخزون فرعية (أوراق) ✅
- `5100 تكلفة البضاعة المباعة` — `system_role = 'cogs'` ✅ موجود لكن **`account_type` غير موحّد** (أحياناً «مشتريات»، أحياناً «مصاريف») → قد يقع تحت OpEx في بعض الشركات
- `5110 المشتريات` — `system_role = 'cogs'`، نوعه «مشتريات» ✅
- `4300 / 4350 / 4400 / 4500` — الخصومات والمردودات (Contra) ✅ معرّفة في `CONTRA_ACCOUNTS`

### ب. نتائج قراءة الكود
- `src/pages/ProfitLoss.tsx` يعامل **كل** حساب مصنّف `Purchases` (كل 51xx) كتكلفة مبيعات مباشرة (سطر «المشتريات» فقط)
- **لا يوجد**: بضاعة أول المدة، بضاعة آخر المدة، قيد تسوية المخزون، إعدادات نظام الجرد
- `company_settings` فيها `inventory_costing_method` (FIFO/WAvg للتقييم) لكن **لا يوجد** `inventory_system` (Perpetual/Periodic) — هذا هو الحقل المفقود المحوري
- الميزانية `BalanceSheetPage.tsx` تعرض 1140 تلقائياً **إذا** كان له رصيد. المشكلة أن الشركات اللي ما بتربط أصناف بفواتير الشراء → 1140 يبقى صفر و«تختفي» البضاعة

### ج. الخلاصة المحاسبية (مرجعية)
- **IAS 2 §34:** تكلفة البضاعة تُعترف مصروفاً **فقط عند بيعها**
- **IAS 1 §54(g):** المخزون بند مستقل واجب في الأصول المتداولة
- **معادلة COGS الدولية:**
  ```
  COGS = بضاعة أول المدة + صافي المشتريات − بضاعة آخر المدة
  ```
- في الجرد الدوري (Periodic) — نظام متعارف عليه في كل ERPs عالمياً (SAP, Oracle, Zoho, QuickBooks) — نطبق قيدَي تسوية عند إقفال الفترة

## 2) البنية المقترحة (Root → Leaf)

### أ. توسعة شجرة الحسابات (لا نغيّر رموز موجودة)
| كود | اسم | نوع | ملاحظات |
|---|---|---|---|
| `1140` | المخزون (Parent) | Asset | موجود |
| `1140-01` | مخزون أول المدة | Asset (leaf) | جديد — يحمل رصيد أول الفترة |
| `1140-02` | مخزون آخر المدة | Asset (leaf) | جديد — الرصيد الحالي بعد الجرد |
| `5100` | تكلفة البضاعة المباعة | COGS | توحيد `account_type='مشتريات'` + `system_role='cogs'` |
| `5100-01` | بضاعة أول المدة (COGS section) | COGS (leaf) | جديد — يستقبل قيد فتح |
| `5100-02` | بضاعة آخر المدة (contra COGS) | COGS (leaf, contra) | جديد — يستقبل قيد إقفال |
| `5110` | المشتريات | COGS | موجود |

**قاعدة الحماية:** كل الجديد `is_system_protected = true`، غير قابل للحذف/التعديل.

### ب. الإعداد الجديد في `company_settings`
```
inventory_system            text        DEFAULT 'perpetual'   -- 'perpetual' | 'periodic'
periodic_inventory_enabled  boolean     DEFAULT false
periodic_disclosure_method  text        DEFAULT 'weighted_avg' -- إفصاح IAS 2
```

### ج. جدول جديد `inventory_period_counts` (سجل الجرد الفعلي)
- `period_start`, `period_end`, `count_date`
- `opening_value`, `closing_value`
- `adjustment_journal_id` (رابط قيد التسوية)
- `counted_by`, `notes`, حماية RLS بالـ `user_id/dataOwnerId`
- منع التكرار لنفس الفترة

## 3) قيود التسوية التلقائية (عند إقفال الفترة)

### القيد الأول — عكس بضاعة أول المدة (نقلها إلى COGS)
```
من ح/ 5100-01 بضاعة أول المدة        ×××
    إلى ح/ 1140-01 مخزون أول المدة       ×××
```

### القيد الثاني — إثبات بضاعة آخر المدة (تخفيض COGS + إثبات الأصل)
```
من ح/ 1140-02 مخزون آخر المدة        ×××
    إلى ح/ 5100-02 بضاعة آخر المدة       ×××
```

### النتيجة على قائمة الدخل
```
تكلفة المبيعات
   بضاعة أول المدة              +XXX
   المشتريات                    +150,500
   (−) خصم مكتسب / مردود مشتريات −XXX
   (−) بضاعة آخر المدة           −YYY
   ─────────────────────────
   إجمالي تكلفة المبيعات         =ZZZ
مجمل الربح = الإيرادات − ZZZ
```

### النتيجة على الميزانية
```
الأصول المتداولة
   المخزون                       YYY   ← بند مستقل واجب حسب IAS 1
```

## 4) شاشات وتعديلات الواجهة

### أ. إعدادات المالية → قسم جديد «نظام الجرد والمخزون»
- Toggle: **«تفعيل نظام الجرد الدوري»** مع شرح مبسّط بالعربي
- Dropdown: طريقة التقييم للإفصاح (FIFO / متوسط مرجّح)
- تحذير: لا يمكن تفعيله في فترة فيها حركات مخزون فعلية على `stock_movements` بدون موافقة صريحة (منع الازدواج مع Perpetual)

### ب. شاشة جديدة: **«جرد آخر المدة»** ضمن الشؤون المالية
- اختيار الفترة (شهر / ربع / سنة)
- عرض:
  - بضاعة أول المدة (تلقائي من إقفال الفترة السابقة أو 0)
  - إجمالي المشتريات في الفترة (محسوب)
  - حقل إدخال: **قيمة بضاعة آخر المدة** (يدوي)
  - معاينة قيد التسوية قبل الترحيل
- زر: **«ترحيل قيد الجرد»** → يولّد القيدين تلقائياً في `transactions` بربطهم بـ `inventory_period_counts`
- سجل تاريخي لكل عمليات الجرد + إمكانية عكس القيد (Reverse Entry) عبر `create_reverse_entry()`

### ج. تعديل `src/pages/ProfitLoss.tsx`
- عند `periodic_inventory_enabled = true`:
  - إضافة سطر «بضاعة أول المدة» (من `5100-01` debit)
  - إضافة سطر «(−) بضاعة آخر المدة» (من `5100-02` credit)
- عند `false`: يبقى العرض الحالي كما هو (Perpetual)
- تحديث الـ classifier ليعامل `5100-02` كـ contra-COGS

### د. تعديل `src/pages/BalanceSheetPage.tsx`
- عرض بند «المخزون» تحت الأصول المتداولة **حتى لو رصيده صفر** طالما الحساب موجود ومفعّل (بناءً على IAS 1 §54(g))
- إظهار تفصيل: مخزون أول المدة، مخزون آخر المدة، مخزون جاري (perpetual)

### هـ. تذييل قائمة الدخل — إفصاح IAS 2
- سطر نصي: «طريقة تقييم المخزون: [FIFO / المتوسط المرجّح] — بنظام [الجرد الدوري / الجرد الدائم]»

## 5) حماية النزاهة (Integrity Guards)

1. **منع الازدواج:** trigger على `transactions` يرفض قيد يدوي مباشر على `5100-01` أو `5100-02` أو `1140-01/02` (فقط عبر شاشة الجرد)
2. **قفل الفترة:** لا يمكن إعادة تشغيل قيد الجرد بعد إقفال الفترة (`fiscal_periods`)
3. **التوازن التلقائي:** `SUM(1140-01) + SUM(1140-02)` يظهر ضمن رصيد الأصل الأب `1140`
4. **Balance-sheet parity check:** الأصول = الالتزامات + حقوق الملكية (بعد إضافة صافي الربح المُعدّل)
5. **Migration آمنة:** الحسابات الجديدة تُنشأ لكل شركة قائمة عبر `INSERT ... ON CONFLICT DO NOTHING`، وللشركات الجديدة عبر seed function
