# خطة تنفيذ: تعديل طريقة الدفع بعملات متعددة (بحذر شديد)

## الأهداف المتفق عليها
1. الكاشير يختار عملة الباقي بحرية.
2. الاعتماد على شجرة الحسابات القائمة — الصناديق معرَّفة أصلاً بـ (فرع + عملة + `gl_account_code`)، الدالة `_pos_resolve_cash_gl` تحلّها. الناقص هو استغلالها في وضع الدفع المختلط.
3. واجهة بسيطة وواضحة — لا لخبطة عملات.
4. الترحيل المحاسبي الصحيح: كل سطر يذهب لصندوقه الفعلي (شيكل/دولار/دينار) في `transactions`.

## المرحلة 1 — Migration واحدة لتحديث RPC `change_pos_payment_method`

### التغييرات (بدون كسر أي وظيفة قائمة)
- **حذف** الفحص `CURRENCY_REQUIRES_SINGLE_METHOD` (السطر 67-69) فقط.
- **قبول** حقول جديدة اختيارية لكل سطر في `p_split_payments`:
  - `currency` (افتراضي 'ILS').
  - `exchange_rate` (افتراضي 1).
  - `foreign_amount` (افتراضي = amount حين ILS).
  - `change_amount` + `change_currency` (افتراضي 0/ILS).
- **تحقّق الإجمالي**: مجموع `amount` (بالشيكل) = `order.total` كما هو الآن — بدون تغيير. `foreign_amount × exchange_rate` يجب أن يساوي `amount` بفارق ≤ 0.01، وإلا خطأ `SPLIT_FX_MISMATCH`.
- **تحقّق وجود صندوق GL للعملة**: قبل الإدخال، لكل سطر نقدي بعملة أجنبية نستدعي `_pos_resolve_cash_gl` ونتأكد أنه لا يرجع `box_gl_code` (fallback)، وإلا خطأ صريح `CASH_BOX_MISSING_FOR_CURRENCY` مع hint يوضح العملة والفرع.
- **حفظ في `pos_payments`**: نستخدم القيم الحقيقية بدلاً من إجبار ILS:
  - `amount` = القيمة بالشيكل (كما هو).
  - `tendered` = القيمة بالشيكل (يحافظ على العقد الموثّق في `.lovable-memory/features/pos/shift-close-multicurrency-and-business-day.md`).
  - `currency` = عملة السطر الفعلية.
  - `exchange_rate` = السعر المستخدم.
  - `change_amount` + `change_currency` من المُدخَل.
- **قيود GL**: الكود القائم في السطر 319-372 يستخدم أصلاً `v_tender_currency` ويستدعي `_pos_resolve_cash_gl` — يعمل تلقائياً بعد رفع الحظر. لا تغيير في منطق التوزيع (نسبي حسب `amount/total` مع آخر سطر يأخذ المتبقّي).
- إبقاء كل شيء آخر كما هو: audit log، fiscal period trigger، employee movements، إلخ.

### السلامة
- الدالة SECURITY DEFINER + LANGUAGE plpgsql → atomic في transaction واحدة.
- الفواتير القديمة لن تتأثر (لا backfill، لا تغيير schema).
- fiscal_periods trigger موجود ويمنع التعديل بعد الإغلاق ✅.

## المرحلة 2 — تحديث الواجهة `ChangePaymentMethodDialog.tsx` (تغييرات مُصانة)

### تحسينات الوضوح (بدون Stepper — يبقى ديالوج واحد)
- تكبير حجم الديالوج إلى `max-w-lg` لإعطاء مساحة تنفّس.
- شبكة الطرق: تحويل 3×2 إلى 2×3 (خيار "دفع مختلط" في صف مستقل بارز) لإزالة الخانة الفارغة.

### بنّاء الدفع المختلط الجديد
لكل سطر:
```
[العملة ▾]  [الطريقة ▾]  [المبلغ بالعملة]  ← [x]
                          ≈ ₪ 39.86 (السعر: 3.0106)
```
- زر واحد أخضر "موازنة المتبقّي" يملأ آخر سطر تلقائياً بالشيكل.
- شريط أسفل يعرض: `الإجمالي المطلوب: ₪120.00 | مجموع الدفعات (بالشيكل): ₪120.00 | متبقّي: 0.00`.
- عند اختيار عملة أجنبية: يظهر حقل صغير أسفل السطر "الباقي" + قائمة عملة الباقي (تلقائياً = عملة الدفع، قابل للتغيير).
- تحذير أصفر إذا الصندوق للعملة+الفرع غير موجود (قراءة `cash_boxes` بالواجهة قبل الإرسال).

### قسم "أثر على أدراج العملات" — جديد قبل زر التأكيد
مربّع صغير رمادي:
```
درج ILS: +80.00
درج USD: +12.50 (باقي ₪-3.20 من درج ILS)
درج JOD: ±0
```
يعطي الكاشير ثقة قبل الحفظ.

### تحسينات مشتركة (تنطبق على كل الأوضاع)
- ترتيب البلوكات: طريقة → (تفاصيل حسب الطريقة) → سبب → أزرار.
- زر التأكيد يعطّل مع رسالة سبب واضحة إذا فيه خطأ تحقق.
- الحفاظ على كل شيء يعمل حالياً: employee_account، visa routing، currency change للنقدي الأحادي.

## المرحلة 3 — اختبار يدوي محدَّد (قبل التسليم)

سيناريوهات إلزامية:
1. **حالة قائمة**: تعديل بطاقة → نقدي (شيكل) → يجب ألا يتغيّر شيء في السلوك.
2. **حالة قائمة**: تعديل نقدي شيكل → نقدي دولار → درج USD يظهر صحيحاً في إغلاق العهدة.
3. **جديد**: دفع مختلط 60 شيكل + 60 شيكل (بطاقة+نقدي) → يعمل كالسابق.
4. **جديد**: دفع مختلط 90 ILS + 10 JOD (نقدي كلاهما) لفاتورة 130 ILS بسعر 4 → قيدَين مدين مختلفَين (كاش شيكل + كاش دينار)، درج JOD يظهر +10 في الإغلاق.
5. **حالة الخطأ**: محاولة دفع دينار بدون صندوق دينار للفرع → خطأ واضح بالعربية.

## المخاطر والتخفيف

| خطر | تخفيف |
|---|---|
| قيود مختلطة قديمة تنكسر | لا نمس القيود السابقة — التغيير فقط للاستدعاءات الجديدة |
| صندوق غير معرَّف | فحص مسبق + خطأ فوري قبل حفظ أي قيد |
| توزيع VAT | يبقى كما هو (نسبي حسب حصة السطر من الإجمالي) |
| مطابقة الإجمالي | نبقي شرط `Σamount(ILS) = total` — لا لخبطة |
| كسر السلوك القائم | تغيير RPC يقتصر على رفع حظر واحد + إضافات اختيارية — الوضع الافتراضي (ILS كل السطور) يعطي نفس النتائج بالضبط |
