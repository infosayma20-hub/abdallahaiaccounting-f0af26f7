## الهدف

زرار ساعة 🕒 بجانب «سجل المحوّلة» في نقطة البيع، يفتح شاشة جدولة طلبية مستقبلية. الطلبية تُحفظ الآن، وتظهر للفرع تلقائياً مع صوت تنبيه قبل موعد التسليم بوقت التحضير (افتراضي 20 دقيقة).

## من يستخدمه

- **الكول سنتر**: يجدول طلبية ويحدد الفرع المستهدف (نفس منطق التحويل الحالي).
- **الكاشير في الفرع**: يجدول طلبية لزبون بيجي لاحقاً — الفرع المستهدف = فرعه تلقائياً.

## مسار العمل

```text
1) الموظف يعبّي السلة عادي
2) يكبس زرار الساعة  →  شاشة الجدولة
3) يحدد: التاريخ + وقت التسليم + وقت التحضير (20 د افتراضي)
         + بيانات الزبون (اسم/جوال/عنوان) + نوع الطلبية
         + عربون/دفع مسبق (اختياري)
4) حفظ  →  الطلبية بحالة «مجدولة» (مخفية عن شاشة الفرع)
5) عند وصول (وقت التسليم − وقت التحضير):
   تتحول تلقائياً لـ «واردة» → تظهر بشاشة الفرع + صوت تنبيه
   (نفس مسار الطلبيات المحوّلة الحالي بالضبط)
6) الكاشير يقبلها → تفتح بالسلة → يكمل الدفع والطباعة
   (العربون المدفوع مسبقاً يُخصم من المستحق)
```

## تغييرات قاعدة البيانات

على جدول `call_center_orders` (نفس الجدول لأن مسار الاستقبال بالفرع جاهز عليه):

| الحقل | الوصف |
|---|---|
| `is_scheduled` | هل الطلبية مجدولة |
| `scheduled_for` | وقت التسليم المطلوب |
| `prep_minutes` | وقت التحضير (افتراضي 20) |
| `release_at` | لحظة الظهور للفرع = `scheduled_for − prep_minutes` |
| `released_at` | متى ظهرت فعلياً (تدقيق) |
| `prepaid_amount` | العربون المدفوع مسبقاً |
| `prepaid_method` | كاش / فيزا |
| `prepaid_pos_order_id` | ربط سند قبض العربون |
| `created_channel` | `call_center` أو `pos` (لتمييز طلبيات الكاشير) |

- الحالة الجديدة `scheduled` في عمود `status`، وتتحول لـ `pending` عند الإفراج.
- فهرس على `(user_id, status, release_at)` لسرعة الإفراج.
- تفعيل Realtime موجود أصلاً على الجدول (لا تغيير).

## آلية الإفراج (الأهم — بدون أخطاء)

طبقتان لضمان عدم ضياع أي طلبية:

1. **الطبقة الأساسية (خادم)**: دالة `release_due_scheduled_orders()` + مهمة `pg_cron` كل دقيقة — تحوّل كل الطلبيات المستحقة إلى `pending` وتضبط `released_at`. تعمل حتى لو ما في جهاز مفتوح.
2. **الطبقة الاحتياطية (عميل)**: شاشة الفرع تستدعي نفس الدالة كل 60 ثانية أثناء عملها — تغطي أي تأخير بالـcron.

الدالة **idempotent** (تحدّث فقط الصفوف بحالة `scheduled` و`released_at IS NULL`)، فلا يوجد أي احتمال ظهور مكرر أو صوت مكرر.

## العربون / الدفع المسبق

- عند تسجيل عربون تُنشأ حركة قبض فورية بنقطة البيع (صندوق الوردية الحالية) مربوطة برقم الطلبية المجدولة.
- عند إتمام الطلبية لاحقاً، شاشة الدفع تعرض: الإجمالي − العربون = **المستحق**، وتُطبع على الفاتورة سطر «مدفوع مقدماً».
- محاسبياً: العربون يُسجّل الآن، والفاتورة تُصدر وقت التسليم — بدون ازدواج إيراد.

## واجهة المستخدم

1. **زرار الساعة** في شريط أزرار السلة بجانب «سجل المحوّلة» (للكول سنتر) وبنفس المكان للكاشير، مع Badge بعدد الطلبيات المجدولة القادمة اليوم.
2. **شاشة الجدولة** (Dialog صغير سريع): اختصارات جاهزة (بعد ساعة / بعد ساعتين / بكرا الساعة …) + منتقي تاريخ ووقت + وقت التحضير + بيانات الزبون + العربون.
3. **قائمة «الطلبيات المجدولة»**: عرض القادم، مع أزرار تعديل الوقت، إلغاء، وإفراج فوري («أرسلها للفرع الآن»).
4. **تنبيه الفرع**: نفس صوت وشكل الطلبيات المحوّلة الحالي، مع شارة «مجدولة – التسليم 20:30».

## نقاط تدقيق (حماية من المشاكل)

- منع جدولة وقت في الماضي، ومنع وقت تحضير سالب.
- إذا مرّ وقت الإفراج والفرع مسكّر/ما في وردية → الطلبية تبقى ظاهرة كـ«متأخرة» بلون أحمر ولا تُلغى تلقائياً.
- الأسعار تُخزّن كما وقت الجدولة (نفس منطق التحويل الحالي)، والكاشير يقدر يعدّل قبل الإتمام.
- عدم المساس بأي منطق للطلبيات المحوّلة الحالية — الحقول الجديدة كلها اختيارية وقيمها الافتراضية تحافظ على السلوك القديم حرفياً.
- توقيت القدس (Asia/Jerusalem) في كل العرض والمقارنات.
