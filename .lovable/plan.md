# خطة عمل الزبونة الجديدة - أمواليّ ERP

آخر تحديث: 2026-07-02

الخطة مبنية على ملاحظات الزبونة. مقسّمة لبَتشات صغيرة قابلة للتنفيذ بدون كسر المسارات الحالية.

---

## Batch 1 — تحسينات UX عاجلة ✅ منجز
- زر "ملء الشاشة" (Full-screen) لكشف الحساب AccountStatementV2Page — يوسّع الجدول لأقصى عرض ممكن مع ESC للخروج.
- تحسين حقل التاريخ RtlDateField ليقبل الكتابة اليدوية بصيغة DD/MM/YYYY مع الحفاظ على منتقي التاريخ.
- عرض "آخر سعر بيع" و"آخر سعر شراء" داخل صف الصنف في InvoiceCreatePage — Tooltip صغير.
- التأكد من زر "إلغاء" لمردودات المشتريات (تم — نفس الكود لـ sales_return و purchase_return في ReturnsListPage).

## Batch 2 — الشيكات والدفعات ✅ منجز جزئياً
- تم إضافة زر واضح "دفعة على الحساب" داخل VoucherFormPage فوق لوحة ربط الفواتير — يفعّل وضع Advance مباشرةً (بدون ربط فاتورة، يبقى المبلغ كرصيد مفتوح).
- تم توسعة زر ملء الشاشة ليشمل دفتر الأستاذ العام (بالإضافة لكشف الحساب).
- المتبقي: نموذج شيك مضغوط جديد بأسلوب مصغّر (بديل للـ Dialog الحالي متعدد الأسطر).

## Batch 3 — الأرصدة الافتتاحية الموحّدة ✅ منجز جزئياً
- شاشة OpeningBalancesHub `/opening-balances` تجمع في مكان واحد:
  - أرصدة الحسابات (Trial Balance Import)
  - أرصدة الموردين والعملاء (Contact Opening Balances) ← عدد + رابط لبطاقة العميل
  - أرصدة الصناديق والبنوك بعملاتها ← عدد + رابط للشاشة المعنية
  - رصيد مدين/دائن + مؤشر التوازن (Balanced/Off) في أعلى الصفحة
- رابط سريع لشاشة استيراد Excel للأرصدة (كل قوالب الاستيراد جاهزة سابقاً).
- المتبقي (اختياري لاحقاً): تبويب أرصدة المخزون تفصيلياً + استيراد مباشر داخل الهب.

## Batch 4 — تعدد الفروع والحسابات
- ✅ فلتر مركز تكلفة/فرع أضيف لقائمة الدخل (P&L). ميزان المراجعة يحتويه سابقاً.
- المتبقي: توثيق داخل SettingsPage للفرق بين Cost Center / Branch / Warehouse.
- لوحة "مقارنة فروع" بسيطة داخل Dashboard.

## Batch 5 — تحسينات الفواتير
- عرض آخر 5 حركات لكل صنف في نافذة جانبية داخل InvoiceCreatePage (اختياري بزر).
- "نسخ فاتورة" — زر يعيد إنشاء فاتورة بنفس بنودها كمسودة.
- تحسين طباعة الفاتورة للعملة الأجنبية: عرض المبلغ بالعملتين.

## Batch 6 — تنظيف تقني (خلفي)
- فحص باقي التحويلات النقدية اليتيمة (4 حالات في finance_integrity_fix_log).
- فحص باقي الفواتير المعلقة (82 فاتورة في v_invoices_payment_mismatch).
- تقرير أسبوعي تلقائي عبر Edge Function يرصد أي حركات جديدة يتيمة.

## قواعد التنفيذ
1. لا نكسر أي مسار (route) موجود.
2. لا نمسّ منطق الترحيل المحاسبي إلا بعد اختبار.
3. كل تعديل ينعكس على finance_integrity_fix_log إذا كان يمس بيانات موجودة.
4. UX أولاً — لا نضيف حقول جديدة إلا لو ضرورية.
