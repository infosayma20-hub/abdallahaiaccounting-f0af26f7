# وثائق هوية الموظف (هوية + ملحق الهوية)

## المشكلة الحالية (بعد قراءة قاعدة البيانات)
- جدول `employees` لا يحتوي أي حقل لصور الوثائق باستثناء `photo_url` (الصورة الشخصية فقط).
- تبويب «المستندات» في شاشة الموظف 360 يقرأ حقولاً غير موجودة إطلاقاً: `id_card_url`, `national_id_image`, `contract_url`, `qualification_url`, `cv_url`, `passport_url` → لذلك التبويب فارغ دائماً ويظهر «لا توجد مستندات». هذا سبب الإحساس بأن الشاشة «مش مربوطة».
- صور الهوية الوحيدة اليوم تصل عبر مرفقات نموذج «معلومات الموظف» في مخزن `employee-forms`، وغير مرتبطة بملف الموظف.

## الحل: وحدة مستندات موظف حقيقية

### 1) قاعدة البيانات
جدول جديد `employee_documents`:
- `employee_id`, `owner_id` (مالك البيانات للعزل), `company_id`
- `doc_type` (نص مقيّد: `id_card_front`, `id_card_appendix`, `photo`, `contract`, `cv`, `qualification`, `passport`, `other`)
- `title`, `file_path` (مسار داخل المخزن), `mime_type`, `file_size`
- `uploaded_by`, `uploaded_by_role` (`employee` أو `hr`), `notes`
- `created_at` / `updated_at` + trigger تحديث

صلاحيات RLS:
- الموظف: يرفع ويرى ويحذف وثائقه هو فقط (ربط عبر `auth_user_id` للموظف) — ولا يعدّل وثائق رفعها HR.
- مدير الموارد البشرية / admin / super_admin: رفع وعرض وتعديل وحذف لكل موظفي الفريق (نفس نمط `employee_policy_documents` باستخدام `is_team_member`).
- GRANT للـ `authenticated` و`service_role`.

### 2) التخزين
مخزن خاص جديد `employee-documents` (غير عام) بمسار `<employee_id>/<doc_type>-<timestamp>.<ext>`
- سياسات على `storage.objects`: الموظف على مجلده فقط، وHR/admin على موظفي الفريق.
- العرض عبر روابط موقّعة (Signed URL) — نفس أسلوب `employeeStorageFiles.ts`.

### 3) واجهة الموظف (تطبيق الموظف)
مكوّن جديد داخل تبويب «ملفي» (`EmployeeProfileTab`): بطاقة «وثائق الهوية» فيها خانتان واضحتان:
- **صورة الهوية (الوجه الأمامي)**
- **صورة ملحق الهوية** — مع نص إرشادي صريح: «مطلوب تصوير ملحق الهوية أيضاً».
دعم الكاميرا مباشرة على الجوال (`capture="environment"`)، معاينة مصغّرة، إعادة الرفع، وشارة «تم الرفع / مطلوب».

### 4) واجهة الموارد البشرية (الموظف 360)
إعادة بناء `DocumentsTab`:
- قراءة فعلية من `employee_documents` + الصورة الشخصية من `employees.photo_url`.
- شبكة بطاقات لكل نوع وثيقة مع معاينة صورة، تاريخ الرفع، ومن رفعها (الموظف أم HR).
- أزرار: رفع / استبدال / تنزيل / حذف (حسب الصلاحية)، وتنبيه أحمر عند نقص «الهوية» أو «ملحق الهوية».
- فتح الملفات عبر روابط موقّعة، ودعم PDF والصور.

### 5) تدقيق شاشة الموظف 360
- إضافة `documents` إلى `useEmployee360` ضمن نفس دفعة الجلب.
- إزالة الحقول الوهمية غير الموجودة من `DocumentsTab`.
- عدّاد على تبويب «المستندات» يوضح عدد الوثائق.

## ملاحظات تقنية
- لا مساس بأي منطق مالي أو حضور.
- المسارات: هجرة SQL واحدة + `supabase--storage_create_bucket` + سياسات المخزن، ثم تعديلات الواجهة.
