## الخطة

### 1) قاعدة البيانات (migration)
جدولان جديدان في `public`:

- **`marketing_campaigns`** — بطاقة كل عرض
  - `name` (اسم العرض)، `slug`، `year`، `season` (رمضان/توجيهي/شتاء/افتتاح/عيد)، `start_date`، `end_date`، `status` (historical/active)، `pos_category_ids` (uuid[] للربط الحيّ بـ `pos_categories` عند التفعيل للعرض الحالي)، `notes`، `source` ('imported' | 'live_pos').
- **`marketing_campaign_sales`** — بند مبيعات مفرد (تاريخي مستورد أو مجمَّع من POS)
  - `campaign_id`، `sale_date`، `invoice_no`، `category_ar`، `item_name`، `variant` (الوحدة)، `qty_dine_in`، `qty_take_out`، `qty_total`، `unit_price`، `discount`، `total_amount`، `currency` (NIS)، `customer_name`، `branch_name` (نص موحّد)، `source_file`.
  - فهارس على (campaign_id, sale_date, branch_name, item_name).

RLS: قراءة فقط لـ **super_admin/admin** + قائمة إيميلات معتمدة (مصعب، كمال، `malakybroast@gmail.com`) عبر دالة `public.can_view_marketing_campaigns()`. الكتابة لـ service_role فقط (الاستيراد يمر عبر `supabase--insert`).

### 2) استيراد البيانات
- سكربت Python يقرأ الـ 9 ملفات ويولّد INSERT دُفعي (chunks بـ 500 صف) عبر tool `supabase--insert`.
- توحيد أسماء الفروع، تنظيف التاريخ (نتخلى عن اسم اليوم العربي)، `qty_total = داخل + خارج`.
- إنشاء صف واحد في `marketing_campaigns` لكل ملف مع `source='imported'` + `status='historical'`.

### 3) واجهة "العروض" في بوابة المالك
- تبويب جديد **"العروض التسويقية"** داخل `PortalDashboard.tsx` (ظاهر فقط لـ مصعب، كمال، ولحساب `malakybroast@gmail.com` — check عبر `useAuth().user?.email` + قائمة emails في constant + دالة `has_role('super_admin')`).
- Edge Function `malaki-data` action جديد: `campaigns_overview`, `campaign_detail`, `campaigns_compare` — تُرجع KPIs + سلاسل زمنية + Top items.

مكوّنات الشاشة (`src/pages/portal/tabs/CampaignsTab.tsx`):
1. **بطاقات ملخّص** لكل عرض: إجمالي المبيعات، الكميات، متوسط الفاتورة، عدد الأيام، أفضل فرع، أفضل صنف.
2. **مقارنة تفاعلية**: Multi-select للعروض → رسم Bar/Line (recharts) للمبيعات اليومية، ومقارنة الفروع.
3. **تفصيل العرض**: جدول أفضل 20 صنف، Pie فروع، Line زمني، فلاتر (فرع، صنف، مدى تاريخي).
4. **زر "تفعيل عرض حي"** (للعرض الحالي): يفتح ديالوج لربط `pos_categories` بحملة `status='active'` — البيانات تُحسب من `pos_orders_effective` بدل الاستيراد.

Design: نفس D365 FinanceShell aesthetic المستخدَم في باقي البوابة.

### 4) خطوات التنفيذ
1. Migration (schema + RLS + دالة الرؤية).
2. استيراد البيانات (Python + insert tool).
3. Edge function actions.
4. UI Tab + Charts.
5. تحقق مع المستخدم قبل إضافة **"عرض توجيهي 2026"** الحيّ.

### تفاصيل تقنية
- التخزين: kg NIS فقط (ILS)، بدون تحويل عملات.
- الفروع نص حرفي كما في الملف؛ ماب داخلي `branch_name → branch_id` عند الحاجة للربط بجدول `branches`.
- `qty` استخدمنا `خارج` كأساس للمقارنة (كما وضّحت في وصفك: "الكميات الخارج")، مع الاحتفاظ بـ `داخل` للعرض عند الطلب.
- لا نمس أي جداول محاسبية موجودة — البيانات معزولة تماماً.
