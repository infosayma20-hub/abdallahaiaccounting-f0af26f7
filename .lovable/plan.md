## خطة مشروع KDS + شاشة نداء الزبائن (ميزة عامة لأي مطعم)

### 1. الأهداف
- شاشة تحضير للمطبخ/السخان (KDS) مرتبطة لحظياً بنقطة البيع.
- شاشة نداء للزبائن بعمودين (قيد التحضير / جاهز للاستلام) مع نداء صوتي عربي ثابت.
- ميزة قابلة للتفعيل لأي مطعم عبر إعدادات الشركة/الفرع، بدون أي ربط بالملكي في الكود.

### 2. قرارات يجب حسمها قبل البدء
- ترقيم النداء: نفس رقم الطلب أم رقم يومي قصير يبدأ من 1 كل يوم؟
- نطاق العرض: كل الطلبات أم فقط Takeaway؟
- متى تظهر "قيد التحضير": فور الدفع أم بعد قبول السخان؟
- مدة بقاء "جاهز" قبل الإخفاء (افتراضي مقترح: 5 دقائق).
- إعادة النداء التلقائي بعد كم ثانية؟ وكم مرة؟
- نوع الصوت: TTS من المتصفح، أم مقاطع MP3 مسجّلة مسبقاً (مقترح: مقاطع جاهزة لضمان ثبات الصوت).
- محطات التحضير: واحدة أم متعددة (سخان / مشاوي / بيتزا)؟
- شاشة لمس للسخان أم ماوس/لوحة مفاتيح؟

### 3. المعدات المطلوبة (الحد الأدنى لكل فرع)
- جهاز الكاشير الحالي.
- تابلت أو شاشة لمس صغيرة للسخان (Android/Windows) مثبتة بمنطقة التحضير.
- شاشة كبيرة للزبائن (تلفزيون 43"+ يكفي).
- جهاز تشغيل للشاشة الكبيرة: Mini PC / Android TV / Chromebox.
- سماعات متصلة بالتلفزيون أو بجهاز التشغيل.
- شبكة محلية مستقرة + UPS صغير للكاشير وجهاز شاشة العرض.
- اختياري: طابعة مطبخ حرارية، شاشات إضافية لمحطات تحضير متعددة.

### 4. الإعدادات الجديدة (company_settings + pos_branches)
- `pos_kds_enabled` (boolean)
- `pos_customer_display_enabled` (boolean)
- `pos_voice_call_enabled` (boolean)
- `pos_voice_language` (ar-PS / ar-SA / …)
- `pos_voice_template` (نص النداء، مثلاً: "طلب رقم {n}، تفضل للاستلام")
- `pos_ready_auto_hide_seconds` (افتراضي 300)
- `pos_call_repeat_seconds` (0 = بدون تكرار)
- `pos_call_number_strategy` ('order_number' | 'daily_short')
- `pos_kds_show_order_types` (مصفوفة: dine_in, takeaway, delivery)
- `pos_kitchen_stations` (مصفوفة محطات اختيارية)

### 5. مخطط البيانات
- استخدام `kitchen_tickets` الموجود (pending/preparing/ready) وإضافة:
  - `display_number` (text) — رقم النداء القصير اليومي إن استُخدم.
  - `station` (text, nullable) — محطة التحضير.
  - `ready_at`, `delivered_at`, `last_called_at` (timestamptz).
  - `call_count` (int default 0).
- جدول جديد `kds_call_events` لتسجيل كل نداء (للتحليلات وإعادة النداء عبر شاشات متعددة).
- تفعيل Realtime على `kitchen_tickets` و`kds_call_events` ضمن RLS حسب `company_id` و`branch_id`.

### 6. التدفق
```text
Cashier (/pos)
   │ create order
   ▼
pos_orders ──trigger──► kitchen_tickets (pending)
                              │ realtime
                              ▼
                    Kitchen (/pos/kitchen)
                    pending → preparing → ready → delivered
                              │ on ready
                              ▼
                    kds_call_events (insert)
                              │ realtime
                              ▼
            Customer Display (/pos/order-display?branch=...)
            يمين: preparing   |   يسار: ready (+ صوت)
```

### 7. الشاشات
- **/pos** (موجود): زر "إرسال للمطبخ" يظهر فقط عند تفعيل KDS.
- **/pos/kitchen** (موجود — يُحدَّث): تصميم لمس كبير، أعمدة الحالات، فلتر محطة، زر "جاهز" واضح، صوت تنبيه عند ورود طلب جديد.
- **/pos/order-display** (جديد): ملء الشاشة، عمودان، آخر رقم جاهز بحجم ضخم، تشغيل الصوت العربي عند الانتقال إلى ready، زر إخفاء بعد المدة المحددة.
- **إعدادات > نقطة البيع > شاشة المطبخ والنداء** (جديد): كل الحقول أعلاه + زر "تجربة الصوت" + معاينة الشاشة.

### 8. الصوت العربي
- المرحلة 1: مقاطع MP3 مُولّدة مسبقاً عبر ElevenLabs (صوت عربي ثابت):
  - "طلب رقم"، أرقام 0–9 ومئات شائعة، "تفضل للاستلام".
  - تركيب المقطع في المتصفح (AudioContext + queue) لضمان نطق واضح وموحد.
- المرحلة 2 (اختيارية): دعم Web Speech API كخيار احتياطي لمن يريد لغات أخرى.

### 9. ربط الشاشات بأموالي
- شاشة العرض تستخدم رابطاً عاماً للفرع + توكن جهاز (device token) دون تسجيل دخول كامل، يُولَّد من إعدادات POS.
- شاشة المطبخ تستخدم نفس آلية دخول الكاشير (PIN) مع دور `kitchen_staff` جديد.
- كل شاشة مرتبطة بـ `branch_id` صريح ولا ترى طلبات فروع أخرى (RLS).

### 10. الأمان والعزل (متعدد المستأجرين)
- RLS على `kitchen_tickets` و`kds_call_events` حسب `company_id` (عبر `get_team_owner_id`).
- توكن شاشة العرض محدود الصلاحية: قراءة فقط لتذاكر الفرع المحدد، وبدون أي بيانات مالية.
- لا أسعار ولا أسماء زبائن على شاشة العرض — أرقام فقط.

### 11. مراحل التنفيذ
1. الإعدادات + الـ migration (أعمدة + جدول الأحداث + RLS + Realtime).
2. توليد مقاطع الصوت العربية ورفعها إلى Storage.
3. تحديث `/pos/kitchen` (UI لمس + محطات + صوت تنبيه).
4. بناء `/pos/order-display` (عمودان + صوت + إخفاء تلقائي).
5. ربط إنشاء طلب POS تلقائياً بـ `kitchen_tickets` (trigger).
6. صفحة إعدادات KDS داخل إعدادات نقطة البيع + توكن شاشة العرض.
7. اختبار يوم كامل في الملكي ثم تعميمها كميزة قياسية.

### 12. ما لن يُلمس
- تدفق الدفع، إغلاق الوردية، الترحيل المحاسبي، المخزون — لا تغيير.
- سلوك المطاعم التي لم تُفعِّل الميزة يبقى كما هو (Default = false).

### تفاصيل تقنية مختصرة
- Frontend: React صفحات جديدة + hook `useKdsRealtime(branchId)` فوق Supabase channel.
- Backend: trigger `pos_orders_after_insert` ينشئ `kitchen_ticket` إذا `pos_kds_enabled`.
- Audio queue: Web Audio API بتشغيل ملفات MP3 مرتبة من Storage عام للفرع.
- Device auth: جدول `pos_display_devices` (token, branch_id, role, expires_at).
