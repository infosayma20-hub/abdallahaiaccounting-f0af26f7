# شاشة تتبع الطلبيات (Order Tracking) — خطة التنفيذ

هدف: رابط مستقل لكل فرع يفتح شاشة "تتبع الطلبيات" لمدير الفرع، تقيس الزمن من **لحظة طباعة فاتورة الزبون** حتى **الضغط على «تم التسليم»**، على مستوى الطلبية ومستوى الصنف، مع أهداف زمنية (SLA) افتراضية 5–12 دقيقة قابلة للتخصيص (المشروبات/الجاهز = فوري).

## 1. قاعدة البيانات

### جدول جديد: `pos_order_tracking` (سطر لكل طلبية)
- `order_id` (FK pos_orders, unique), `company_id`, `branch_id`, `business_date`
- `printed_at` — نقطة بدء العدّاد (من `receipt_last_print_at` وإلا `created_at`)
- `delivered_at`, `delivered_by_name`, `delivered_by_user`
- `target_minutes` (هدف الطلبية = أكبر هدف بين أصنافها)
- `elapsed_seconds` (محسوبة عند التسليم) + `is_late`

### جدول جديد: `pos_order_item_tracking` (سطر لكل بند)
- `order_line_id` (FK pos_order_lines, unique), `order_id`, `company_id`, `branch_id`
- `product_id`, `product_name`, `qty`
- `printed_at`, `delivered_at`, `delivered_by_name`
- `target_minutes`, `elapsed_seconds`, `is_late`

### جدول جديد: `pos_prep_sla` (إعدادات التوقيت)
- `company_id`, `scope` (`default` | `category` | `product`), `category_id`, `product_id`
- `target_minutes` (افتراضي عام: 8، حد أدنى 5، أقصى 12)، `is_instant` (المشروبات/الثلاجة → 0 دقيقة)
- بذرة أولية: افتراضي 8 دقائق، وفئات المشروبات/الحلويات الجاهزة = `is_instant`.

### آلية التعبئة
- Trigger على `pos_orders` عند تحديث `receipt_last_print_at` (أو عند إتمام الطلب إن لم تُطبع): ينشئ صف تتبع للطلبية + صفوف تتبع للبنود، ويحسب `target_minutes` لكل بند من `pos_prep_sla` (منتج ← فئة ← افتراضي).
- دالة `pos_mark_item_delivered(line_id)` و`pos_mark_order_delivered(order_id)`: تختم الوقت، تحسب `elapsed_seconds` و`is_late`، وتسليم الطلبية يختم كل بنودها غير المسلّمة.
- GRANT + RLS: قراءة/تحديث لأعضاء الفريق (`is_team_member`)، وقراءة عامة محدودة للرابط العام عبر دالة `security definer` بالـ slug (بدون كشف أي بيانات مالية).
- إضافة الجدولين إلى `supabase_realtime` لتحديث الشاشة لحظياً.

## 2. الرابط لكل فرع
- مسار جديد `/track/:slug` يعتمد `branches.public_slug` (موجود مسبقاً؛ نولّد slug للفروع الناقصة).
- صفحة عامة بدون تسجيل دخول (كما شاشات العرض الحالية)، تقرأ عبر RPC `get_branch_tracking_board(slug)` التي ترجّع الطلبيات النشطة + بنودها + العدّادات فقط.
- زر نسخ الرابط لكل فرع داخل إعدادات نقطة البيع (تبويب الفروع).

## 3. شاشة تتبع الطلبيات
- بطاقة جديدة في **لوحة نقطة البيع** باسم «تتبع الطلبيات» (متاحة للجميع حسب صلاحيات POS)، إضافة للرابط العام لكل فرع.
- التخطيط: شبكة بطاقات طلبيات، كل بطاقة:
  - رقم الطلبية/العرض، نوع الطلب، الكاشير، وقت الطباعة.
  - **عدّاد الطلبية** (كبير) — أخضر ضمن الهدف، برتقالي قرب الهدف، أحمر متأخر.
  - قائمة البنود، ولكل بند **عدّاده الخاص** + هدفه + زر «تم التسليم» للبند.
  - زر «تم التسليم» للطلبية كاملة.
- الترويسة: **لوجو الشركة** من الملف الشخصي (`useCompanyLogo`)، والزاوية اليمنى السفلية: **شعار Unify ERP + الاسم** (`BRAND.logos.primary`).
- تحديث لحظي عبر Realtime + مؤقّت محلي كل ثانية، RTL، ومناسب لشاشة كبيرة.

## 4. التقارير
- تقرير جديد `POSOrderTrackingReport` ضمن **تقارير نقطة البيع** (تبويب «تتبع الطلبيات»):
  - متوسط زمن التسليم للطلبية والبند، نسبة الالتزام بالهدف، أبطأ الأصناف، الأداء حسب الساعة/الكاشير/الفرع.
  - فلاتر التاريخ/الفرع القائمة نفسها + تصدير Excel.
- إضافة نفس التقرير في **بوابة الإدارة (شاشة المالك) ← المزيد** كبطاقة/تبويب مختصر (ملخص + أعلى التأخيرات).

## 5. الإعدادات
- قسم «أهداف زمن التحضير» في إعدادات نقطة البيع: تعديل الهدف الافتراضي، وهدف لكل فئة/منتج، وتعليم أصناف «جاهزة فوراً».

## تفاصيل تقنية
- المرجع الزمني هو `printed_at` من الخادم؛ العدّادات في الواجهة محسوبة من فرق الزمن مع `Date.now()` لتجنّب انحراف أجهزة الفروع.
- بنود بدون طباعة (طلبات مؤجلة/ملغاة) تُستثنى؛ الطلبيات الملغاة تُغلق تلقائياً بلا احتساب تأخير.
- لا تعديل على منطق المحاسبة أو الطباعة الحالي — الإضافة قراءة/كتابة على جداول تتبع منفصلة فقط.
