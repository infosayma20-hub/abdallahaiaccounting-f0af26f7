# Project Rules

- Use “يونيفاي” / “UNIFY” exclusively in all user-facing forms, documents, printouts, emails, notifications, and defaults; retain legacy `amwali` identifiers only where changing them would break storage, routes, database objects, integrations, or historical links.- Barcode goods receiving writes only via SECURITY DEFINER RPCs (`receiving_*`, `assign_receiving_session`) on `procurement_receiving_*`; stock/GL stay in the existing purchase-invoice flow. Why: workers must not see prices or post financials.
- Purchase order lines reference `procurement_items` (purchasing catalog); stock always goes to `procurement_items.inventory_product_id` via `ensure_procurement_item_product`, and invoice lines carry `procurement_order_item_id` for cumulative received qty. Why: order item ids are not products ids (FK failed silently before).
- Warehouse receiving is a standalone employee workspace: entry requires an active receiver flag or an assigned receiving session, and its back action returns only to the workspace chooser. Why: prevent warehouse staff from falling into the administrative ERP shell.
- Employee hot-drink sales use the dedicated atomic RPC and `[EMPLOYEE_HOT_DRINK]` order-line marker; the first two drinks per POS business day are half price, later drinks are full price, and all marked lines bypass stock movements. Why: keep limits, employee debt, and inventory treatment auditable and race-safe.
- Attendance rules (timezone Asia/Hebron, 06:00 business-day start, gap/grace/tolerance/cap defaults) live only in DB function `attendance_departure_rules()`; `recompute_attendance_day`, `hr_backfill_attendance` and the UI (`applyAttendanceRules` via `useDepartureCap`) read from it, and derived-gap dismissals are saved inside `hr_update_attendance_day` (`p_dismissed_gaps`). Why: one source of truth and atomic HR edits.
- POS screen/print language comes only from `branches.receipt_language` (admin, default ar). Why: no impact on other branches.
