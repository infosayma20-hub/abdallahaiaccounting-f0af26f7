# Project Rules

- Use “يونيفاي” / “UNIFY” exclusively in all user-facing forms, documents, printouts, emails, notifications, and defaults; retain legacy `amwali` identifiers only where changing them would break storage, routes, database objects, integrations, or historical links.
- Barcode goods receiving writes only via SECURITY DEFINER RPCs (`receiving_*`, `assign_receiving_session`) on `procurement_receiving_*`; stock/GL stay in the existing purchase-invoice flow. Why: workers must not see prices or post financials.
- Purchase order lines reference `procurement_items` (purchasing catalog); stock always goes to `procurement_items.inventory_product_id` via `ensure_procurement_item_product`, and invoice lines carry `procurement_order_item_id` for cumulative received qty. Why: order item ids are not products ids (FK failed silently before).
- Warehouse receiving is a standalone employee workspace: entry requires an active receiver flag or an assigned receiving session, and its back action returns only to the workspace chooser. Why: prevent warehouse staff from falling into the administrative ERP shell.
- Employee hot-drink sales use the dedicated atomic RPC and `[EMPLOYEE_HOT_DRINK]` order-line marker; the first two drinks per POS business day are half price, later drinks are full price, and all marked lines bypass stock movements. Why: auditable and race-safe.
- Attendance rules (timezone Asia/Hebron, 06:00 business-day start, gap/grace/tolerance/cap defaults) live only in DB function `attendance_departure_rules()`; `recompute_attendance_day`, `hr_backfill_attendance` and the UI (`applyAttendanceRules` via `useDepartureCap`) read from it. Why: one source of truth.
- HR attendance edits never mutate raw `attendance_events`: they go only through RPC `hr_save_attendance_day`, which stores corrections in `attendance_day_overrides`, applies explicit break diffs and gap dismissals, recomputes via `_attendance_effective_events`, and audits — all in one transaction. Why: edits survive new punches and stay auditable.
- POS screen/print language: `pos_terminals.receipt_language` (set in the new-device wizard) wins, else `branches.receipt_language`, else ar. Why: per-station config.
- Purchase-order edits go only through RPC `update_procurement_order` (gate: `procurement_order_edit_block_reason`), which keeps line ids, forbids qty below invoiced qty or deleting received lines, and logs before/after in `procurement_order_edits`. Why: keep links and audit.
- Direct receiving (no PO): `employees.can_direct_receive` users act only via `direct_receiving_*` RPCs on `procurement_orders` (`source='direct_receiving'`, review_status flow); submit creates a receiving session so the invoice flow posts stock/GL; temp lines are linked via `direct_receiving_link_temp_line` before invoicing. Why: finance stays in one audited path.
- Camera scanning uses shared `POSBarcodeScanner` (native `BarcodeDetector`, else `barcode-detector` ponyfill with local `public/zxing/` WASM); inputs normalize via `src/lib/barcode.ts`, processed serially; server RPCs match via `_barcode_variants()`. Why: fast offline scans, none dropped.
- Barcodes are unique per tenant across products.barcode and product_barcodes (trigger enforce_unique_product_barcode); one product may have many barcodes. Why: a scan must resolve to exactly one product.
- Fresh sign-ins keep login visible while `/apps` preloads; navigate after gates and animation settle, with a watchdog. The launcher has a persisted five-column grid sortable by long press, cached favorites, and locked apps under `متقدمة`. Why: synchronized cards without flashes or clutter.
- Role checks in RLS policies and helper functions (admin, hr_manager, accountant_*) must always be AND-combined with a tenant check (is_team_member / is_same_team / company owner); only super_admin may be global. Why: every company owner holds 'admin', so a bare has_role leaks data across tenants.
- POS v2 is the default for all POS users; legacy `/pos` remains in v2 “More” for the current tab, sharing all sales/print logic. Demo tenants alone bypass Print Bridge via `is_current_tenant_demo()`. Why: approved rollout without breaking workflows.
- Business units (multi-shop on one tenant): `business_units` + `branches.business_unit_id` + `warehouses.business_unit_id` + `product_business_units` (unlinked product = visible everywhere); active workspace is per-device via `useBusinessUnits`, picker only for 2+ units. Why: one subscription/ledger with per-shop analytics.
- Employee stock count (`employees.can_stock_count`): only via `stock_count_*` RPCs; name/price apply at once into `product_edit_log`, counts go to `stock_count_entries` and post an adjustment only on review (delta vs balance at approval). Why: no unreviewed stock changes.
- Inventory costing: `stock_movements` is the only cost source; trigger `tg_inventory_costing_engine` feeds `inventory_cost_*` per product×warehouse; opt-in via `initialize_inventory_costing`, method locked after activation, changed only via audited RPCs. Why: one auditable cost.
